## Goal, status and completion predicates

Give the induction loop a packaged skill, so that a business reader can do every
step of [Find the rule your auditors are really using](../../../../docs/tutorials/learn-rules.md)
by asking Claude Code through a skill:

1. score a model's rules against host labels (`gnd measure --labels`);
2. discover candidate rules from one population (`gnd discover`);
3. export labelled populations to a rule learner, run a learner the user names,
   and import its rules back with GND's re-check (`gnd export ilp`,
   `gnd import ilp-rules`);
4. hand every proposal to review (`gnd-model-evolve`).

The skill proposes and never admits. Admission stays a reviewed act owned by
`gnd-model-evolve`. A real learner (Popper) is not installed and stays optional.

Today the tutorial's "What you did" table shows five rows asked as "a plain
request" and one (step 6) through `gnd-model-evolve`. Steps 1 to 5 use the four
commands above; steps 2 and 4 also run the example's stand-in learner, which is
not a GND command. The IK6 record calls this "four of the six steps" by counting
commands (record 010, Boundary, F8). Both readings leave the same gap.

Planning only. The [IS1 draft spec](phase-IS1-spec.md) awaits plan approval and
its own owner gate.

Completion requires:

1. **IS1:** one new packaged skill (name per D1) ships in the wheel and in both
   plugin hosts. Its routes to and from its siblings are pinned in
   `tests/test_packaged_skills.py`. Every inventory, installer, marketplace,
   AGENTS.md and invocation-guard pin moves by the named edits in the IS1 spec,
   and each moved pin goes red on the pre-IS1 tree. The IK skill census test
   stops counting files added after the IK milestone (D8). The tracked links are
   generated by `uv run gnd install --symlink --project --force`, and
   `uv run gnd doctor --project` exits 0.
2. **IS2:** the learn-rules tutorial shows a skill prompt at every step and no
   plain request. Every prompt that the page presents as a recording is a
   committed recording of a real Claude Code run of the skill over the `refunds`
   example, rendered by `tools/render_replay.py` and pinned by
   `tests/test_replays.py` (D11). Every failure in a recording is explained
   beside it. Every number the page states still has its string pair in
   `tests/test_ik6_walk.py`. The commands page remains the one runnable walk and
   exits as documented. The installed-candidate docs check passes in both wheel
   origins.
3. Every phase has an approval, focused checks, an independent diff review, a
   refactoring review and a record. Close has review evidence from the
   instrument the owner selects (D13), a question sweep, a PR and separately
   recorded owner acceptance.

No delivery date is committed.

## 2. Contract proposal and product behavior

One skill, provisionally **`gnd-induce`** (D1), at
`src/gnd/skills/gnd-induce/SKILL.md`. Its slash entry point in Claude Code is
`/gnd:gnd-induce`. It has four intents and a fixed handoff:

| Intent | GND command(s) | Writes | Ends with |
|---|---|---|---|
| **score** a model's rules against host labels | `gnd measure MODEL --labels MANIFEST --out OUT` | the measure report | the numbers, verbatim, per rule |
| **discover** rules from one population | `gnd discover MODEL POP --out PROPOSAL --report REPORT --actor ID --requested-at T [--families …]` | a discovery report and, when anything is emitted, an evolve proposal | the emitted and suppressed counts, and each candidate read back in plain English |
| **learn** a rule with a named learner | `gnd export ilp … --target neutral\|popper --out DIR`; the learner the user names; `gnd import ilp-rules … --reported-coverage RUN --out PROPOSAL` | an export directory, the learner's outputs, an evolve proposal only if GND's coverage equals the claim | the re-check result, or the named refusal and a stop |
| **hand off** | none | none | a route to `gnd-model-evolve` naming each proposal file |

**Inputs fixed before any run:** the model, the label manifest or population,
the audit actor and request time (so outputs are reproducible), and new output
paths. An existing `--out` (exit 11) means choosing a new path, never deleting.

**Reactions, not meanings** (IS-R3): exit 0 → report; exit 3 → report the named
refusal verbatim and stop; exit 11 → pick a new output path; any other non-zero
→ report verbatim and stop. The meaning of each exit stays in `--help`.

**Refusals** (each one sentence with one home in the skill):
- never applies, confirms or edits the model, and never hand-edits a proposal;
- never installs a learner, and never runs one the user did not name;
- never writes a run record's `covered` sets from GND's own import result;
- after a coverage refusal, never changes the claim and imports again;
- never blends measure cells into one accuracy number;
- never copies host values or paths into a proposal, a report or a public page;
- never touches git (the record contract's denial pattern).

**Routes** (exact edges fixed in the IS1 spec):
- *into* the skill, from the `gnd-orm-core` workflow index (required by its
  test), the `gnd-export` ILP paragraph, the `gnd-dev-session` grounding
  paragraph, `gnd-solve` Station 6, and the `gnd-model-evolve` induced-provenance
  bullets;
- *out of* the skill, to `gnd-model-evolve` (the handoff), `gnd-orm-core` and
  its provenance and population references, `gnd-export` (derivation exports
  are not this skill), `gnd-dev-session` (measure over a synth corpus is not
  this skill) and the record contract.

`gnd-solve` gets no new station number (D7); the stable station numbers stay
pinned by `test_t25`.
