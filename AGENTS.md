# GND development agreements

Use [process-phase](.codex/skills/process-phase/SKILL.md) for numbered milestone work.
The complete normative references are shipped in both real discovery roots;
keep twins byte-for-byte and executable-mode identical. The owned compatibility
[plan-review-panel](.codex/skills/plan-review-panel/SKILL.md) requires an explicit
handoff to the maintained advisory panel. No automatic sibling execution.

Default `auto=false`; owner approval precedes implementation. User authorization
persists for its named scope; never invent approval. Read the whole effective
plan and applicable carryovers when harvesting a phase. Plan authorship is not
publication authority. Certification/recertification needs an explicit current
owner request for a named subject and scope; old certificates describe old bytes.

Credential-free development follows CONTRIBUTING. Optional live review uses the
explicitly selected terminal-agent tools and credentials; never execute or source a repository `.env`.
Import only required names from a documented trusted environment, never print
values. The maintained panel requires parent credentials; its explicit launcher
may parse the owner's trusted Codex file as data before invocation.

GND-managed discovery links are generated by the own installer. On a fresh clone,
adopt tracked links once with uv run gnd install --symlink --project --force,
then uv run gnd doctor --project. Receipts are machine-local and gitignored.
Never maintain links by hand. Source-owned units remain source-owned
until an explicit accepted handoff. No target publisher exists during P2 staging.
