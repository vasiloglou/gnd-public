## Standing rules

The example reads validated contextual rows, stable admission markers and
bounded JSON. Selection and materialization are by verified input order,
with explicit caps on documents, targets and bytes. Run the admission
step before composing. The same structured edge rules serve all queries
in each family. The policy JSON owns the allowed relation and transfer
table. The model is its checked application and will keep declaration
and byte digests. Counts, exact proof exits and distinct mutated inputs
supply the observable controls.

## Goal

Use the composed output of saved-opinion admission as the base for
documented lineage and qualified transfer. Exit 0 on the accepted chain
queries and 2 on the missing queries. A derived path is accepted because
its specific directed edges are witnessed. Track both the contextual
assertion facts and the verified resolution association behind them.

## Design and reuse

| Capability | Search and observed component | Decision |
|---|---|---|
| Derived paths and cycle reports | guarded recursion, ring acyclic, witness trace | Reuse structured derivation, the deontic ring checker and witness/replay v2 |
| Identity provenance | composition resolution source lineage | Reuse the admitted assertion facts' source coordinates and LI2 resolution checks |
| Saved review projection | contextual assertion admission | Reuse LI4 admission over the extended contextual model, keeping the same three raw fact types |
| Baseline corpus | literature fixture builders and harness | Adapt the authored development annotations into the contextual shape. Score named ordered paths after construction |
| Reserved scoring | C6 digest pin and local retained key | Use a temporary scoring input after the model and path policy are committed |

In examples/literature/lineage/model.orm.yaml reuse the LI4 statement,
work and passage roles. Add documented lineage step and justified transfer
step as derived facts over (descendant, ancestor, assertion). The assertion
role is the String passage identifier of the already admitted statement
and is unique in the example's construction. The LI4 externally identified
Assertion type has no strict primitive, as checked with ModelIndex, so the
passage identifier supplies a typed witness address. The base proof still
carries the original work and passage pair. Bind asserts and own-finding
and require both participant kinds to be sense. Each direct
rule matches one approved predicate literal. The set is fine-tunes,
implements, extends, component-use and training-on-outputs. These may
chain. Evaluated-as, compared-against, inspired-by and taxonomic-membership
stay asserted when supported and do not supply either derived step.

Use existing qualification roles in the transfer example. A cited
assumption sits in condition. A cited interface sits in regime. Both are
part of the reviewed statement. A transfer step requires conditional and
both fields must be concrete. No transfer proof can use an unqualified
assertion or an unspecified field.

Add two binary recursive derived ancestry relations and a binary direct
lineage projection. The direct projection carries a deontic acyclicity
constraint. Keep the effect of that warning orthogonal to acceptance
and retain every asserted edge. A witness target may name the direct
step and its exact assertion ID, or cite the recursive binary query.
Score the ordered named path by its directed edges as well as its endpoints
to prevent an alternate route from accepting a false path.

The assembly example reads a closed source annotation file with original
passage IDs, participants, relation, contextual fields and saved rubric
disposition. It binds and runs the LI4 admission route for each document.
Sources are composed with the explicit source-only decision pairs
already agreed in the corpus and any separately reviewed fixture pairs.
The writer binds the admitted population bytes and sidecar to each
source. The accepted polysemy examples keep their distinct spellings.
The resolution covers participant names and uses same decisions for
verified unchanged joins. The source lookup must refuse undeclared
or stale subject/receipt material. Any missing composition record
keeps witness claims pending.

A bounded example constructor takes `assemble(example: Path, model: Path,
annotations: Path, out: Path) -> None`. Its closed input has schema
`literature-lineage-input/1`, `sources` and `decisions`. Each source has
`id`, a relative `document` path under the example, `sha256`, `work`,
and `statements`. A statement has an original `passage` identifier,
`start` and `end` byte offsets in that source, actor and object with two
participant kinds, the predicate and context roles of the LI4 example,
and a `disposition`. Supported, contradicted, stretched and
insufficient-evidence map through the existing rubric. An explicit
missing disposition generates no receipt. Each decision lists two
source and spelling keys and a same or different decision. Generation
derives exact decision coordinates from the admitted source rows.
The caps are 32 sources, 32 statements per source and 128 decisions.

The closed run carries `sources/manifest.json`, the admitted populations
and their bound sidecars, the per-source admission bundles and
`composed.population.json` plus `composition.json`. The scorer entry is
`score(model: Path, run: Path, answer_key: Path) -> dict`. It caps the
number of labelled paths and nodes per path, deduplicates witness targets,
and compares their proof states. Its result carries exact support and
exclusion counts and closed query exits. A checked proof refusal cannot
be counted as an excluded path. Reserved scoring retains aggregate
counts and bound digests in the milestone record.

The examples/literature/lineage/path-policy.json is a closed versioned
table of the five chainable and four non-chainable predicates, each with
lineage and transfer arms. Transfer requires both the reviewed assumption
and interface on every edge. The scorer reads only the named paths and
labels of its split, reports support and exclusion numerators, and retains
no reserved label text or path names in committed output.

## Scope

The example uses the public-scale corpus and an isolated reserved score,
while preserving the ordinary witness format and existing composition route.
The date interoperability story remains assigned to the successor.

## Size

One contextual extension model, a policy table, bounded assembly and
scoring script, a development and adversarial corpus, and focused tests.
Estimate 300 lines of producer and scoring code and 160 test lines.

## Approval instrument and implementability sweep

Corpus-first. Concrete rule bindings and proof targets are declared before
implementation. The closed constructor can materialize ordinary anchored
composition directories. Every derived edge has a positive contextual row
and a source assertion key, so it can be traced using version-2 witness
lineage. A closed record changes its digest whenever decision indexes
change. The policy's four nonchaining relations, missing transfer slot,
and same-domain false chain all have discriminating inputs. The separate
reserved key can be digest-checked locally after the policy commit.
