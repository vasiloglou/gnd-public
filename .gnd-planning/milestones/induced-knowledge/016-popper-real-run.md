# A real Popper run through the ILP bridge (IK5-Q5)

**The owner approved installing Popper on 2026-10-27:** "A real Popper run needs
your yes to install Popper. -> yes". This record covers the first run of a real
learner on GND's Popper rendering. GND's code is unchanged. Popper stays outside
the repository (IK-R8): it is not a dependency and not a test lane.

## Result in one paragraph

Popper v5.0.1 loads GND's `bk.pl`, `exs.pl` and `bias.pl`. Then it **crashes
after 22 s without a program**, because `bias.pl` declares no argument
directions and Popper calls a comparison on unbound variables. Two diagnostic
variants, which are scratch copies of the export and not GND output, locate the
cause:
- **Directions added:** the crash is gone, but the result is `NO SOLUTION`,
  because mainline Popper has no `magic_value_type` and so has no constants.
- **Constants added the mainline way** (one unary predicate per amount value):
  Popper learns the stand-in's rule in 0.4 s, with precision and recall 1.00.
  GND then refuses the clause (`unknown-predicate: 'c500'`).

With the constant folded by hand into `gt_t_amount(V1,500)`, the import passes.
GND's re-check agrees (covers 4, support 4/4), and the `provenance.induction`
block holds the run. Three code changes need a spec gate (P1 to P3 below). None
was made here.

## Answers

1. **Does Popper accept the rendering?** It reads all three files: clingo
   parses `bias.pl`, and SWI consults `bk.pl` and `exs.pl`. **It cannot learn
   from them.**
   - The run crashes on unbound comparison arguments (P1).
   - Even with directions, there is no constant to compare against (P2).
   - Two observations are harmless:
     - SWI rejects `type(wrong,(ex,))`, but Popper reads bias through clingo,
       and its own examples use the same 1-tuple form.
     - `bk.pl` interleaves predicates, which gives only `discontiguous`
       warnings.
2. **Does the printed program parse?**
   - The bare clause parses: probe a reached the fragment check.
   - The printed block does not (probe b, P3).
   - **IK5-Q2 was not exercised:** no learned clause has a quoted atom, so no
     SWI octal escape appeared. IK5-Q2 stays open as it was.
3. **Does the import's coverage check pass?** Not for any program Popper printed
   from GND's rendering, because none was printed. For probe c it passes: GND
   covers exactly the reported set {harbor, market, airport, station}, and the
   learner and GND agree on every example.
4. **Does `provenance.induction` hold the run (the IK2 "block's fit")?** Yes, for
   what it was designed to hold. In probe c it has:
   - `inducer {popper, 5.0.1}` and `method ilp-popper`;
   - the 4 `examples`, empty `counterexamples`, and `support 4/4`;
   - the `manifest_sha256`;
   - the three digests: E, CLAUSES `b56ebb2e…` and run `571177f3…`.

   **Residual:** the block cannot say that the learner ran on a modified bias,
   or that the clause was rewritten after learning. The digests bind the
   rewritten text, and the rationale reads "learned by popper 5.0.1". The
   learner version is the caller's free text; Popper reports none, and its
   package metadata says 5.0.0. This fits as long as P1 to P3 make rewriting
   unnecessary. Otherwise the block needs a field for post-processing.
5. **What did Popper learn, compared with the stand-in's `V1 > 500`?** The same
   rule.
   - Popper's form: `f_refund_amount(V0,V3,V1), c500(V2), gt_t_amount(V1,V2)`.
   - Imported, probe c gives the guarded constraint `refund_amount(refund=$v_v3,
     amount=$v_v1) => $v_v1 <= 500`. This equals the stand-in's proposal except
     for the variable spelling (`$v_v3` where the stand-in has `$v_v0`) and the
     rationale.
   - Popper found it as the size-4 optimum. Before that, it reached a size-12
     program that simply listed the four flagged amounts. It reached the
     threshold rule only once constants were supplied.
