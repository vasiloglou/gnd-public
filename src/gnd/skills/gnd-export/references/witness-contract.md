# Certificate versions 1, 2 and 3

See the [closed wire schema](witness.schema.json) and [workflow](../SKILL.md).
Bindings include the existing model identity, SHA-256 of canonical candidate
model_dump JSON and each fixed reference's raw-byte SHA-256. Changed bound input
is stale before inference is attempted. Metadata participates in candidate
identity. Reference hashes are recomputed from consumed bytes.

Nodes are consecutive numbered base occurrences, grounded rule instances or
comparison premises. Every edge points backward. Body occurrences precede where
premises in declaration order. Rule instances retain clause index, typed variable
bindings and head tuple. Bases refer to a candidate or fixed-reference occurrence;
a computed tuple cannot be asserted as a base. Only nodes reachable from success
roots are admitted. Alternative finite proofs and shared DAGs are accepted.

Supported: positive, range-restricted single/multiple clauses, grounded recursion,
scalar heads/body literals, Integer and integral Number, String/Boolean equality,
and canonical ISO Date comparisons. Every dependency clause must be in scope.
Negative premises, aggregates, semiderived claims, opaque rules, Float, nonintegral
Number, DateTime and expression trees are refused. Date/Duration arithmetic has
no admitted derivation site and is refused during model intake.

Fixed ceilings: 10 MiB certificate/request bytes, container depth 64, 256 targets,
10,000 nodes, 40,000 edges, 100,000 binding cells and attempted production joins,
proof depth 128, 4,096 UTF-8 bytes per scalar, 128 numeric digits, and 20,000
expanded-view visits. Callers may lower, never raise, these ceilings. Resource
refusal is a separate non-success claim. Compact DAG replay does not expand trees.

The byte ceiling applies to in-memory intake as well as files. A generated proof
that cannot fit the certificate wire budget returns work refusal 4 without a
certificate. A supplied oversized certificate returns input refusal 3. Expanded
views contain bounded explanation occurrences and are never replayable input.

Generated byte accounting includes canonical export's final newline.

## Version 2: composed populations

`gnd witness MODEL COMPOSED --targets T --composition RECORD` writes version
2 over a population made by `gnd compose`. The record must bind the model and
population bytes (its raw-byte SHA-256s), or the request is refused (3). The
binding adds `composition_sha256`, the raw-byte SHA-256 of the record file.
Every base node adds `sources`: the record's source facts
`{source, fact_type, fact_index}` for that composed fact, with `source` in the
record's id form (1 to 64 letters, digits, `.`, `_` or `-`). `origin.kind` stays
`candidate`. Each source fact's anchors, in its own source's sidecar, locate
spans in that source's document; they bind values to ranges and prove nothing.

`gnd replay ... --composition RECORD` replays version 2: a different record
digest is `binding-stale` (3), a base node whose `sources` differs from the
record is `proof-invalid` (1), and the graph then replays as for version 1.
Version 2 without `--composition` is `composition-required` (3); version 1
with it is `binding-stale` (3); a record that does not bind the model and
population, or an unreadable record, is `input-invalid` (3). Replay checks
that the witness agrees with the record; it does not re-derive the record
from the sources, which `gnd check --composition --sources` does. Witness views list `sources` as ids and
indexes. `--composition` excludes `--reference-root` (64): composition refuses
reference populations. Version 1 is unchanged.


## Version 3: rooted model origins

`gnd witness ROOT POP --targets T --raw --out CERT` resolves the authored
include root and emits version 3. `gnd replay ROOT POP CERT` resolves the same
root before examining any model-origin claim. Either command accepts
`--flat-model FILE --flattening-record FILE` as a pair. Supplied files must
match the rooted, re-derived bytes from the
[flattening contract](../../gnd-orm-core/references/representation-format.md#extraction-flattening-record).
Without the options, the commands derive the same projection in memory.
The binding uses the raw SHA-256 of the canonical flattening record in
`flattening_sha256`. A valid include-free root continues to produce versions
1 or 2.

Each node carries `model_origin` with `origin`, `original_address`,
`composed_address` and `element_id`. These are the origin entry for the
node's fact type, or the declaring rule fact type for a comparison node.
The element ID is a string. A base node's `origin` still identifies the
candidate or reference fact occurrence. Version 3 additionally uses
`composition_sha256` and the base nodes' `sources` when a reference-free
composition record is supplied.

Replay parses the certificate, authenticates the rooted model and its
provided artifacts, then binds the composition if supplied. A changed
bound digest is `binding-stale` (3). A structurally valid but forged model
origin or fact occurrence is `proof-invalid` (1). The unrooted model-byte
intake cannot resolve authored includes. An incomplete option pair exits 64.
The same witness byte and work ceilings govern the stamped output.
