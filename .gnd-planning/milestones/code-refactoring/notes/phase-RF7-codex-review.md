2. **MVP blocking — shared inheritance traversal can invent an unambiguous primitive.** [model_queries.py](<worktree>/src/gnd/model_queries.py:99) shares one `seen` set across sibling parent walks. I loaded a valid model with values `q: Integer`, `p: String`, `z: String`; entities `x→q`, `y→p`, `w→z`; and literal-`True` inheritance `a→[x,y]`, `b→[x,w]`, `r→[a,b]`. `primitive_for("a", …)` and `primitive_for("b", …)` each return `None` because each is ambiguous. `primitive_for("r", …, variant="strict")` **returns `"String"`**, because the second walk skips the already visited `x`. Expected: `None`. The predecessor’s copied `seen` set did not cause this result in its truthy walk. This refutes C5’s ambiguity behavior on an admitted model.

3. **MVP blocking — a routed sidecar reads past the cap and loses its error adapter.** [synth/provenance.py](<worktree>/src/gnd/synth/provenance.py:289) calls `Path.read_text()` before shared policy checks size, and catches `JSONDecodeError` but not the policy’s byte-cap `ValueError`. With `Path.read_text` returning 10 MiB plus one byte, `read_sidecar("sidecar.json")` performs the full read, then raises raw `ValueError("JSON input exceeds byte cap")`. Expected: a bounded read and a `SidecarError` refusal. This leaves C2’s before-read cap and domain error contract unmet for this consumer.

4. **Hardening — a mutating callback can erase duplicate-key evidence.** [input_policy.py](<worktree>/src/gnd/input_policy.py:74) invokes `object_pairs_hook(items)` before checking duplicates in that mutable list. `loads('{"x":1,"x":2}', object_pairs_hook=lambda items: (items.clear(), {})[1])` **returns `{}`**; expected duplicate-key refusal. The built-in routed hooks I sampled do not mutate the list, so this is a public callback guarantee gap rather than a demonstrated production-route bypass.
