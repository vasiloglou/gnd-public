Part 1 · docs/reference/disclosure.md (new)

Choose what GND discloses

GND reads your populations, so many of its outputs can quote population values: a why-not sample, a witness certificate, a sensitive role in a check report. Whether that is acceptable depends on who reads the output.

  • Behind your own interface, the reader is you or your service. Values help: they say which fact to add or fix.
  • In front of customers, the reader may be anyone whose requests your service forwards. Values should stay inside.

One setting, the disclosure mode, says which of these situations GND is in. To try it on an example, see Run GND behind your interface or in front of customers.

The three states

Mode Declared sensitive roles in check reports Witness, replay, why-not, Lean and Soufflé outputs Requests for values
unset redacted unless --unredacted value-free unless --raw; the Python functions return raw values allowed
internal shown raw, in the CLI and the Python API allowed (already granted)
customer redacted value-free, in the CLI and the Python API refused, exit 3 or DisclosureRefused

Unset is the default and changes nothing: every output and every option behaves as it did before the mode existed.

internal acts as if every value option were passed: --unredacted on the check family, --raw on witness, witness-view, replay, why-not and the Lean and Soufflé exports, and the matching Python keywords.

customer withholds two kinds of value:

  • in check-family reports, the roles your model declares sensitive with redact: true (see declare what is sensitive);
  • in witness, replay, why-not, Lean and Soufflé outputs, every population value. The Python functions return what the CLI prints by default: api.why_not returns the redacted view, and api.witness and api.replay return the default view with no raw certificate.

It does not withhold values in check-family messages for roles you have not declared. Declare them.

Set the mode

Set the environment variable of the process that runs GND:

export GND_DISCLOSURE=customer

or pass the root option, before the subcommand:

gnd --disclosure internal why-not model.orm.yaml population.json --fact-type cited_by

The value is exactly internal or customer. GND resolves the mode in this order:

  1. If GND_DISCLOSURE holds anything else (Customer, a trailing space, the empty string), every command that can emit values refuses with exit 3, even when --disclosure is given. A mistyped lock never opens.
  2. If GND_DISCLOSURE=customer, --disclosure internal is refused with exit 3. The option can tighten the mode, never loosen it.
  3. Otherwise --disclosure, if given, applies to that invocation; else the environment; else the mode is unset.

The option itself is checked like any other argument. A value other than the two names, or a second --disclosure, is a usage error, exit 64:

set +e
gnd --disclosure Customer validate model.orm.yaml 2>&1 | tail -1; echo "exit ${PIPESTATUS[0]}"
gnd --disclosure customer --disclosure customer validate model.orm.yaml 2>&1 | tail -1; echo "exit ${PIPESTATUS[0]}"

gnd: error: argument --disclosure: invalid choice: 'Customer' (choose from internal, customer)
exit 64
gnd: error: --disclosure may be given at most once
exit 64

The Python API has no per-call keyword. It reads the environment, and, when it runs inside a gnd command, that command's mode. customer from either wins.

What customer mode refuses

Every request for values is refused, not quietly downgraded, so nobody mistakes a redacted answer for the raw one.

Request under customer Command line Python
--unredacted on a check-family command; unredacted=True exit 3 DisclosureRefused
--raw on witness, witness-view, replay, why-not, export lean, export souffle*; raw=True exit 3 DisclosureRefused
gnd --disclosure internal … with GND_DISCLOSURE=customer exit 3 —
a malformed GND_DISCLOSURE exit 3 DisclosureRefused

A refused command prints nothing on stdout and one line on stderr that names the option or the variable, never a value. DisclosureRefused is exported from gnd.api and is a ValueError. The how-to shows each refusal.

Outputs that are the same in every mode

These outputs do not follow the mode, and none of them takes a value option. Do not route them to a customer.

Output What it emits Why it is unchanged
gnd exp run session feedback, attempts and results; EvaluationSession.check_with_feedback declared redaction, always applied The session contract fixes it, and feedback goes to agents that may be external providers, so internal must not lift it.
EvaluationSession.observe the caller's own population It returns what the caller passed in.
gnd discover candidate constraints; never value candidates for redacted roles Its proposals name positions, not values.
gnd export ilp undeclared values in its learner input; refuses declared roles Its job is to hand values to a learner you chose.
gnd fidelity the extracted facts it measures Its input is your own extraction case.
gnd doccheck the population values a rendered document misses Its input is your own rendering case.

Child processes

Under customer, GND passes GND_DISCLOSURE=customer to the processes it starts: the agents of gnd exp run, the stations of gnd solve and the reviewers of gnd review panel. Under internal or unset it passes nothing, so a child never gets more disclosure than it would have on its own.

Passing the mode on sets a default for the child, not a lock: an agent controls its own environment.

Who customer mode protects

Customer mode protects the end users of an operator-controlled wrapper: a service that turns a customer's request into GND command-line arguments or gnd.api keywords. Such a caller cannot get values out by asking for them.

For code that runs inside the GND process it is a guard, not a lock: that code can change the environment or call internal functions. Do not run untrusted code in the process.

One signal remains by design. A why-not answer in customer mode still carries the near-miss counters. A caller who supplies a --row learns whether the population holds a value spelled like theirs up to case, spacing and punctuation (see values spelled differently). Here the claim names the work "Field Notes", which the population spells "FIELD NOTES":

python -c "import gnd, pathlib, shutil; shutil.copytree(pathlib.Path(gnd.__file__).parent / 'examples/quoted_claims', 'quoted_claims', dirs_exist_ok=True)"

GND_DISCLOSURE=customer gnd why-not quoted_claims/model.orm.json quoted_claims/spelling-gap.pop.json \
  --fact-type certified --row quoted_claims/claim.json \
  | python -c "import json, sys; b = json.load(sys.stdin)['clauses'][0]['blocker']; print(b['near_miss_count'], b['near_misses'])"

1 redacted

The count says one row of authored matches after normalization; the values stay withheld.

Declare what is sensitive

Check-family redaction follows the model. Mark a whole fact type or one role, as described in the representation format:

fact_types:
  - id: has_email
    reading: "{Customer} has email {EmailAddress}"
    roles:
      - { object_type: customer_code, role_name: customer }
      - { object_type: email_address, role_name: email, redact: true }

The packaged disclosure example declares this role; the how-to runs it in each mode.

Part 2 · docs/how-to/disclosure-mode.md (new)

Run GND behind your interface or in front of customers

Use this when one GND installation serves two kinds of reader. Your own team, behind your interface, wants the population values that explain a failure. A customer, reached through your service, must not see them. One setting, the disclosure mode, tells GND which reader it is serving. The full rules are in the disclosure reference.

Files on GitHub

  • disclosure/model.orm.yaml: a support desk's contacts, with the email role declared sensitive
  • disclosure/population.json: one customer with two email addresses
  • this page's Markdown source

The example

A support desk records each customer's email address. The model says a customer has at most one, and marks the address as sensitive:

roles:
  - { object_type: customer_code, role_name: customer }
  - { object_type: email_address, role_name: email, redact: true }

The population gives customer c-1 two addresses, so the check fails. Copy the example:

python -c "import gnd, pathlib, shutil; shutil.copytree(pathlib.Path(gnd.__file__).parent / 'examples/disclosure', 'disclosure', dirs_exist_ok=True)"

The blocks below print three fields of the check report: the violation message, the offending facts and the redaction mode. Save the filter once:

cat > show.py <<'PY'
import json, sys
verdict = json.load(sys.stdin)["verdicts"][0]
print(verdict["message"])
print(verdict["offending_facts"])
PY

With no mode set: as before

Without a mode, GND behaves as it always has: the declared role is redacted unless you ask for it with --unredacted.

gnd check disclosure/model.orm.yaml disclosure/population.json --format json | python show.py

[REDACTED INSTANCE DETAIL]
[{'redacted': True, 'roles': ['has_email.email']}]

The check still fails with exit 1. The report says which constraint failed and which role was withheld, but not the addresses.

Behind your interface: internal

Set the mode on the root command, before the subcommand, or in the environment of the process that runs GND:

gnd --disclosure internal check disclosure/model.orm.yaml disclosure/population.json --format json | python show.py

Each customer plays 'has_email' with at most one combination of the other roles — violated: customer 'c-1' has 2 facts.
[{'customer': 'c-1', 'email': 'ann@example.com'}, {'customer': 'c-1', 'email': 'ann.lee@example.com'}]

internal acts as if every raw option were passed. Your team sees the two addresses and can decide which one to keep.

In front of customers: customer

Set the mode in the environment of the service that faces customers, so no request can loosen it. In production you export it once in that service's environment; here it is set for one command:

GND_DISCLOSURE=customer gnd check disclosure/model.orm.yaml disclosure/population.json --format json | python show.py

[REDACTED INSTANCE DETAIL]
[{'redacted': True, 'roles': ['has_email.email']}]

The verdict is the same; only the values are withheld.

Requests for values are refused, not downgraded

A customer's request might be turned into --unredacted by your service. Under customer GND refuses it with exit 3 and prints nothing on stdout, so nobody mistakes a redacted answer for the raw one:

GND_DISCLOSURE=customer gnd check disclosure/model.orm.yaml disclosure/population.json --unredacted

gnd: error: --unredacted is refused in customer disclosure mode

The root option can tighten the mode but never loosen it:

GND_DISCLOSURE=customer gnd --disclosure internal check disclosure/model.orm.yaml disclosure/population.json

gnd: error: --disclosure internal is refused when GND_DISCLOSURE=customer

A mistyped value is refused too, so a misspelled lock never opens:

GND_DISCLOSURE=Customer gnd check disclosure/model.orm.yaml disclosure/population.json

gnd: error: GND_DISCLOSURE must be 'internal' or 'customer'

Why-not and witness answers

The mode also covers the commands that explain a derivation: witness, witness-view, replay, why-not, and the Lean and Soufflé exports. This uses the quoted_claims example from Repair a claim that does not derive. In its spelling-gap.pop.json the claimed quotation is missing because the work the claim calls "Field Notes" is recorded as "FIELD NOTES".

python -c "import gnd, pathlib, shutil; shutil.copytree(pathlib.Path(gnd.__file__).parent / 'examples/quoted_claims', 'quoted_claims', dirs_exist_ok=True)"

and --raw is refused:

GND_DISCLOSURE=customer gnd why-not quoted_claims/model.orm.json quoted_claims/spelling-gap.pop.json \
  --fact-type certified --row quoted_claims/claim.json --raw

gnd: error: --raw is refused in customer disclosure mode

From Python

The Python API reads the same environment variable. A request for values under customer raises DisclosureRefused, a ValueError:

import os
os.environ["GND_DISCLOSURE"] = "customer"
from gnd import api
try:
    api.check("disclosure/model.orm.yaml", "disclosure/population.json", unredacted=True)
except ValueError as error:
    print(type(error).__name__, error)

DisclosureRefused unredacted=True is refused in customer disclosure mode

What the mode does not change

  • gnd exp run session feedback, gnd discover, gnd export ilp, gnd fidelity and gnd doccheck behave the same in every mode. Do not route their output to a customer.
  • Values in check messages for roles you have not declared with redact: true are not withheld. Declare every sensitive role.
  • Under customer, the processes GND starts (the agents of gnd exp run, the stations of gnd solve) receive GND_DISCLOSURE=customer. Under internal or no mode they receive nothing extra.

Values in the answer

With no disclosure mode set, the Python API returns raw values, like api.witness, and the CLI prints a redacted view: samples, constant roles and an unavailable term's binding read "redacted", and the answer carries "view": "redacted". Unreleased: disclosure mode (2026-11-01)

One GND installation can now serve readers behind your interface and customers (issue #70). Set GND_DISCLOSURE or the root option --disclosure to internal or customer; unset changes nothing.

  • Child processes receive GND_DISCLOSURE=customer only under customer.
