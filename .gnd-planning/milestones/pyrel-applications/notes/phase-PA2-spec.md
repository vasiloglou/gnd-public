## Proposed design and bounded grammar

Admit only version2, derivation=derived, storage=computed, exact structured rule
keys body/head and optional negate. No recursive/disjunctive/semiderived/opaque
rules. Body1..8 positive atoms and negate0..8 atoms use the PA1 typed binder;
head exactly binds every declared output role using positively bound variables.
Typed literals remain allowed in body/negation; literal heads remain outside the
precise integrated fragment, matching the existing parity compiler. Negated variables must be bound positively and primitive
compatible. Reject unknown roles/facts, extra fields, malformed lists and cycles
before native execution. Order derived heads deterministically by dependencies
from both positive and negative atoms; declaration order cannot decide semantics.

ApplicationOracle seeds only asserted facts into its existing typed native
relations. Derived population rows are claims only. Translate each admitted rule
with native where/select and model-specific not_. Retrieve and deduplicate
complete native tuples and bound them before inserting these computed results
into the derived native relation with distinct row ordinals. Python enumeration
is loading native output, never computing policy; this preserves uniqueness
counts on derived facts instead of collapsing every derived ordinal to0; downstream rules and all_eligible read computed facts. No GND import,
Python join/filter policy, or oracle script import is permitted. Python controls
shape, order, budgets, canonical tuple formatting and claim set comparison only.

Every declared relation retains explicit coverage/list admission, including
negative premises and derived claims, even when positive results are empty.
Existing input/declaration/integer/result ceilings remain. Before each computed
join, conservative work product uses measured predecessor relation counts;
refuse above100000 combinations. Refuse any computed/query result above10000.
No universal derivation claim or broader ORM fragment is added.

Derivation records use the PA0 frozen shape: identity, status, missing and extra
role dictionaries. All exact missing/extra sets are sorted/deduplicated; native
computed extensions may be exposed separately if needed by PA3 with an explicit
schema test. Any mismatch rejects acceptance (exit1), incomplete/error precedence
stays PA1. all_eligible uses computed eligibility even when claims disagree.
