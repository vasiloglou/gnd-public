## 4. Standing rules, bound

1. **Totality.** Every derivation key the lowering reads is validated. Anything
   outside §6.3 is refused by name.
2. **Bounds.**
   - The input row cap is 1 MiB of JSON.
   - GND's validator forbids recursive value invention, so every fixpoint is
     finite over the input's values.
   - A time-bound test runs a 500-edge recursive derivation (§8, row 5).
3. **Validation order.** `load_model_bytes` runs first, so models GND refuses
   (unstratified, unbound, type errors) never reach the lowering.
4. **One walk.** Derived heads are lowered in GND's stratum order, in the same
   pass that builds the relations.
5. **One home.** The relation each constraint reads (§5.3) is decided in one
   function.
6. **Measurement.** A corpus generated by `gnd.api.check` (§8, row 1).

## 5. GND's semantics this phase reproduces (measured)

### 5.1 The derivation verdict

There is one alethic verdict per structured derived head, in `derivations[]`.

| Claim in the population | `derived` | `semiderived` |
|---|---|---|
| head not in `covers`, no rows | unchecked, `derivation-not-covered`, exit 4 | same |
| rows present, head not covered | input refused, exit 3 | same |
| exactly the computed rows | pass | pass |
| extra rows | fail, unsound | pass |
| missing rows | fail, incomplete | fail, incomplete |
| both | fail: incomplete, then unsound | fail: incomplete |

Each finding's witness is one row, `{role: value}` in declared role order. It is
the first missing or extra row when the rows are sorted by the identity tokens
of their values (`extensions._identity_token`: `["string",v]`,
`["number",[n,d]]`, `["boolean",v]`, compared as UTF-8 bytes).

### 5.2 Exits

1 for a violation, then 4 for unchecked, then 2 for vacuous, then 0. Derivation
verdicts count like constraint verdicts.

### 5.3 What constraints and upper rules read

| Head | Constraints read | Upper derivations read |
|---|---|---|
| `derived`, covered | the claimed rows | the computed rows |
| `derived`, not covered | nothing (empty) | the computed rows |
| `semiderived` | the computed rows | the computed rows |

### 5.4 Aggregates

- The group key is the head's variables other than `as`.
- Contributions are deduplicated by (`over` values, `of` value).
- An empty group has no row.
- In a rule with an aggregate, every `where` is post-aggregate.

## 6. Design

### 6.1 Derivations are requirements too

Each structured head `h` gets a computed relation `h_derived`, defined by its
clauses in stratum order. The derivation check is then two requirements over
`h_derived` and the claimed relation `h`:

```python
m.where(h_derived(a, b)).require(h(a, b))        # incomplete: every computed fact is claimed
m.where(h(a, b)).require(h_derived(a, b))        # unsound: every claimed fact is computed (derived only)
```

The DuckDB report turns their denial rows into GND's derivation verdict
(§5.1). The LQP version states the same two requirements. Coverage stays a
property of the input: a head that is not covered is reported unchecked, and
its requirements are not evaluated.

### 6.2 Lowering a clause

- Body atoms become `m.where(...)` atoms; constants stay as literals.
- `negate` atoms become `not_(atom)`. Variables in a negated atom are bound by
  the body; GND's validator enforces this.
- `where` comparisons become PyRel comparisons.
- `head` becomes `.define(h_derived(...))`.
- Several clauses become several `define`s into one relation.
- A recursive clause reads `h_derived` itself. PyRel computes the fixpoint;
  this was measured in PL13a's closure helper.
- Aggregates become `aggregates.<fn>(*over, of).per(*group)`, bound to the
  `as` variable. `count` counts distinct (`over`, `of`) tuples, and `sum` sums
  over them, which is GND's deduplication. A post-aggregate `where` compares
  the bound variable.
- Body atoms over a derived head read `g_derived`, never the claim (§5.3).

### 6.3 Supported, and refused by name

| Supported | Refused by name (later phase or out of scope) |
|---|---|
| positive body, constants, `negate`, `where` with `< <= = >= > !=` | `div`, `round`, `sqrt`, `floor`, `ceil`, `haversine`: float tier, with undefined cases |
| several clauses, headed or shared head | `mod`: undefined at zero |
| recursion (self and mutual) | `avg`: exact rationals in heads |
| aggregates `count`, `sum`, `min`, `max` | opaque string rules (their meaning depends on the rest of the model) |
| function heads and terms `add`, `sub`, `mul`, `neg`, `abs` | date terms (PL14), operations (PL15) |
| `derived` and `semiderived` | subtypes (still refused) |

With the partial functions refused, no supported rule can be "unavailable", so
GND's term-failure path is not reachable here.

### 6.4 Cardinality (PL13a-Q1)

Today the DuckDB report decides cardinality by recounting a member listing in
Python. Instead, it reads the denial rows of the `count` requirements it prints.
The LQP version gains the empty-universe minimum: when `min >= 1`, it also
requires that the universe is not empty.

### 6.5 Readable names

- Variables take the role names of the first role sequence (`student`,
  `course`, `term`), or the object type's name for a single-variable rule
  (`course`, `credits`).
- Reserved and duplicate names get a suffix only when they collide.
- The witness keys GND prints (`$`-names) are unchanged.
