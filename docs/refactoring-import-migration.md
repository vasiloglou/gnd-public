# Migrating imports after the GND refactor

The [migration table](assets/refactoring-import-migration.tsv) lists each historical spelling alongside its migration target and observed first-party uses. Look up the complete import path. Each historical spelling has one migration target. The historical move column records the intermediate names. A row marked “keep current import” identifies a defining home that requires no migration. Two validation wrappers bind different rule IDs. Keep the corresponding SPEC or CONCLUSIONS rule ID when calling their common target directly.

The first public release carrying this notice retains the live compatibility names. The release owner will select any removals under [issue #297](https://github.com/vasiloglou/gnd-public/issues/297) in a later, separately approved retirement phase. The three unused checker cycle helpers were retired earlier under FU5 and have no replacement. [Retirement record](https://github.com/vasiloglou/gnd-public/blob/83777050/.gnd-planning/milestones/rule-check-followups/006-phase-FU5.md).

For an ordinary import, use the migration target. For a test patch, locate the module that looks up the object at call time. A function imported into a module retains that module's binding when a different namespace is patched. For example, the conformance test patches `gnd.conformance.service.model_file_sha256`, where the consumer reads it. Session publisher patches target `gnd.exp.session_runtime`. Keep façade patches for callers that intentionally look up the façade dynamically. The patch columns list possible sites to inspect before changing a test.

The table covers the 847 literal inventory rows, the 479 RF4 named moves, and the 47 RF8 predecessor imports. A symbol may appear more than once. Each row shows the release disposition. Import/use and patch columns report static observations in the package and tests. This scan includes aliases, literal patch paths and common module/attribute patches. Dynamic lookup, local shadowing, platform-specific behavior and external users require separate inspection before retirement. A dash means the scan found no site. Third-party users may still depend on that name.

Reproduce the table from the repository root with `uv run python .gnd-planning/milestones/refactoring-followups/evidence/F7/audit.py`. For the compatibility history, see the [original inventory](https://github.com/vasiloglou/gnd-public/blob/83777050/.gnd-planning/milestones/code-refactoring/notes/shim-inventory.md).
