## Findings

1. **The renamed provenance digest is not the CLI’s lookup.** [cli.py:6364](<worktree>/src/gnd/cli.py:6364) and [cli.py:6927](<worktree>/src/gnd/cli.py:6927) still call `_prov.model_digest`, although [provenance.py:228](<worktree>/src/gnd/synth/provenance.py:228) makes `validated_model_sha256` the new name. Replacing the new name with a failing monkeypatch would leave sidecar creation and measurement using the old alias. Retarget both lookups and add a consumer test that patches the new name and observes the effect. This is an implemented lookup defect; it does not imply the current digest bytes differ.

2. **The RF2 scan control does not inspect a scan’s scope.** [test_rf2_helpers.py:210](<worktree>/tests/test_rf2_helpers.py:210) builds its own fixed set of modules, then checks that the moved functions belong to that set. It never checks the modules visited by the source scans. A scan could stop visiting `gnd.artifacts` while this test stays green. Reproduce in a disposable copy by removing `artifacts.py` from a scan walk and running this test; then plant a forbidden network import in that file to test the actual guard. This is a verification defect, not evidence that the current scans miss the file.

3. **The exit allocation guard misses ordinary assignment forms.** [test_rf2_helpers.py:147](<worktree>/tests/test_rf2_helpers.py:147) recognizes only `Assign` with a constant value. A new `_EXIT_EXTRA: int = 19` outside `exits.py` would violate centralization yet leave this guard green. Plant that declaration in a disposable copy as the negative control, then cover annotated and computed allocations. The current literal `EXIT_*` allocations I inspected are in `exits.py`; this finding concerns the gate’s ability to keep them there.
