## 4. Standing rules, bound

1. **Totality.** A bot's output must be a valid steps document. Anything else
   counts as a failed attempt, with the reason fed back.
2. **Bounds.** At most 5 attempts per question. Each bot call gets a time
   limit. The PyRel check runs once per attempt.
3. **One home.** One shared core module runs the loop, the checks and the
   publishing for every example.
4. **Measurement.** Each example's corpus is checked by GND and PyRel
   (agreement on every plan).

## 5. What the reader runs (from the C2 mockup)

```text
python course/app.py ask "Plan Maya's spring semester. She really wants Machine Learning." --backend pyrel
```

The app shows each attempt: the plan, the checker's verdict, and the feedback
given to the bot. On acceptance, the app executes the plan. Executing writes
the new state, which becomes the next question's starting state.

## 6. Design

### 6.1 Shared core (`src/gnd/examples/plan_apps/core.py`)

- `check(example, plan, backend)`.
  - GND backend: `gnd.api.transition`.
  - PyRel backend: the program generated by `gnd export pyrel --rules duckdb`,
    cached per model digest and run with `--pre --steps`.
  - Both return one structure: the exit code, and the failures
    `[{where, check, status, witness, message}]`.
- `execute`: publishes the post-state only after the chosen backend accepts.
  - GND backend: `transition.computed_post`.
  - PyRel backend: the generated program's new `--emit-post FILE`, which holds
    the asserted facts of the last state plus its computed derived facts.
  - The file is written to a fresh path and then renamed into place.
- `ask(question, bot, backend, attempts)`: the loop. The bot gets the question,
  the model's sentences (the verbalizer's), the operations, the current state
  and the previous attempts' feedback. Its plan is checked; when the plan is
  refused, the failures go back to the bot.

### 6.2 The bot interface

A bot is a command. It reads one JSON document on stdin:
`{question, rules, operations, state, attempts: [{plan, failures}]}`. It writes
a steps document (operations and bindings) on stdout.
- **Digests.** The app adds them, so the bot never handles them.
- **Stand-ins.** Each example ships a deterministic stand-in bot,
  `stand_in_bot.py`, that reproduces the documented story from the feedback,
  for tests and docs.
- **PL17.** Real models sit behind the same interface (Claude Code, and
  OpenRouter through `tools/openrouter_gateway.py`).
- **Feedback.** It names the check (rule id, or operation and precondition),
  the step, and the witness: the offending facts, or for preconditions the
  grounded atom. That closes PL15-Q2 for the apps.

### 6.3 The five examples

| Example | Question | Story (attempts) | Capabilities |
|---|---|---|---|
| Course | "Plan Maya's spring semester. She really wants Machine Learning." | prerequisites missing → a course not offered → accepted | recursion, aggregate sum, frequency, exclusion, operations, precondition, dynamic rule (grades) |
| Clinic | "Refill Sam's prescriptions today." | a refill too early (date_add over the interval) → an interacting pair → accepted | dates, durations, multi-clause interaction rule, a deontic warning, a textual rule left unchecked |
| Access | "Give Bob access to payroll; Carol approves." | an approver inside the management chain (recursive) → accepted with an outside approver | recursion, negation, exclusion (requester and approver), create |
| Trip | "Plan three days in Lisbon under 900 EUR." | over budget (sum) → overlapping bookings → accepted | aggregate sum with a guarded comparison, dates, uniqueness, frequency |
| Lease | "Set up the rent schedule for this lease." | a due date outside the lease term → accepted | dates, value ranges. Anchoring of extracted facts is checked by `gnd verify` (GND only, A1 L6), and the page says so |

Each example folder holds:
- `rules.md`, the free-text rules;
- `model.orm.yaml`;
- `state.pop.json`;
- `plans/attempt-N.steps.json`, the documented attempts;
- `stand_in_bot.py`;
- `app.py`, a launcher;
- `README.md`.

The models are written as `gnd-model-from-text` would write them. The
recordings in PL17 show the skill doing it live.

## 11. Implementation findings

- **The GND verbalizer crashes when given a Path for a model with
  aggregates.** The bot gets the free-text rules instead of the verbalizer's
  sentences.
- **GND's `computed_post` omits derived facts.** The app adds them with
  `evaluate_derivations`, so the published state is accepted as the next
  starting state.
- **Grouping key.** GND's failure message varies from state to state, so
  grouping keys on the witness.
