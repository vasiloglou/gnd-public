# Release preparation approval stories

Non-authoritative fixture instrument, not a completed phase record.
For each packaged dispatch/release model: validate; check the supplied seed;
inspect its named deadline failure; check the supplied repair; remove a required
reference and repeat. Compare CLI and API. Neither parser errors nor unrelated
violations count as the intended failure.

Build a release wheel/sdist and separately an sdist wheel. Keep origins separate.
Promotion accepts exact retained files, refuses missing/changed files, never
rebuilds and performs no upload. Contributor checks must reject a broken skill
reference, changed twin or unlabeled sample. Expected outcomes are in answers.json.
