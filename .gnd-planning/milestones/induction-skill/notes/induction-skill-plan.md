## Goal, status and completion predicates

Give the induction loop a packaged skill, so that a business reader can do every
step of [Find the rule your auditors are really using](../../../../docs/tutorials/learn-rules.md)
by asking Claude Code through a skill:

1. score a model's rules against host labels (`gnd measure --labels`);
2. discover candidate rules from one population (`gnd discover`);
3. export labelled populations to a rule learner, run a learner the user names,
   and import its rules back with GND's re-check (`gnd export ilp`,
   `gnd import ilp-rules`);
4. re-check a population after an apply (`gnd check`; D18 (o)) (p1);
5. hand every proposal to review (`gnd-model-evolve`).

The skill proposes and never admits. Admission stays a reviewed act owned by
`gnd-model-evolve`. A real learner (Popper) is not installed here and stays
optional.

Today the tutorial's "What you did" table shows five rows asked as "a plain
request" and one (step 6) through `gnd-model-evolve`. Step 6 also contains a
plain "check the market week again" (`gnd check`) (p1). Steps 1 to 5 use the
four induction commands; steps 2 and 4 also run the example's stand-in learner,
which is not a GND command. The IK6 record counts commands: the IK6-Q1 row of
its open questions says "four of the six steps" are plain requests, and its
Boundary section records "No skill runs the measure, discover, export or import
steps" (F8) (p1). Both readings leave the same gap.

Planning only. The [IS1 draft spec](phase-IS1-spec.md) awaits plan approval and

## 2. Contract proposal and product behavior

One skill, **`gnd-induce`** (D1), at `src/gnd/skills/gnd-induce/SKILL.md`. Its
slash entry point in Claude Code is `/gnd:gnd-induce`. It has five intents and a
fixed handoff:

| Intent | GND command(s) | Writes | Ends with |
|---|---|---|---|
| **score** a model's rules against host labels | `gnd measure MODEL --labels MANIFEST --out OUT` | the measure report | the numbers, verbatim, per rule |
| **discover** rules from one population | `gnd discover MODEL POP --out PROPOSAL --report REPORT --actor ID --requested-at T [--families …]` | a discovery report and, when anything is emitted, an evolve proposal | the emitted and suppressed counts, and each candidate read back in plain English; with `EMITTED 0`, the counts and no handoff (p1) |
| **learn** a rule with a named learner | `gnd export ilp … --target T --out DIR`; the learner the user names; `gnd import ilp-rules … --reported-coverage RUN --out PROPOSAL` | an export directory, the learner's outputs, an evolve proposal only if GND's coverage equals the claim | the re-check result, or the named refusal and a stop. On request it stops after the learner run, with the learner's claim reported as unchecked (p1) |
| **re-check** a population after an apply (p1; D18 (o)) | `gnd check MODEL POP` | nothing | the check output verbatim; it reports only and never edits the model or population |
| **hand off** | none | none | a route to `gnd-model-evolve` naming each proposal file |

**Inputs fixed before any run:** the model, the label manifest or population,
the audit actor (asked of the user, never derived from git or the environment)
(p1) and request time (so outputs are reproducible), and new output paths. For
discover, export and import an existing `--out` exits 11, and the skill chooses
a new path, never deleting. `gnd measure` overwrites its `--out` without an
exit, so the skill confirms the measure output path does not exist before it
runs (p1).

**Reactions, not meanings** (IS-R3): exit 0 → report; exit 3 → report the named
refusal verbatim and stop (a stale label manifest goes back to the user, IS-R11)
(p1); exit 11 (discover, export, import) → pick a new output path; for
`gnd check`, exits 1, 2 and 4 are results (alethic failure, vacuous,
indeterminate) reported verbatim, not refusals, and exit 3 is an input error,
reported and stopped (p2); any other non-zero → report verbatim and stop. The
meaning of each exit stays in its home (IS-R3), not in the skill.

**Refusals** (each one sentence with one home in the skill; exact text in the
IS1 spec):
- never applies, confirms or edits the model, and never edits a proposal;
- never writes or edits a learner's clauses or run record, except to save a
  printed program verbatim and assemble a Popper run record (IS-R11) (p1, p2);
- never writes, edits or re-binds a label manifest; labels come from the user
  (p1);
- never installs a learner, and never runs one the user did not name;
- takes covered sets only from the learner's output or an evaluation the user
  selects, never from a GND verdict (IS-R2) (p1, p2);
- after a coverage refusal, never changes the claim and imports again;
- never combines measure cells into one accuracy number;
- never copies host values or paths into a written or public artifact it
  authors, apart from the learner artifacts of IS-R11 (p1, p2);
- never touches git (the record contract's shared denial, pinned by
  `RECORD_ROUTES`, not one-home) (p1).

**The Popper branch (p1):** the skill names `--target popper` as a branch with
its absent-learner stop. It is unproven on the refunds example: `ilp-bridge.md`
says the rendering has not been run against a real Popper, and sibling PR #51
(not on main) reports that the rendering as written does not run (P1..P3). No
page or checkpoint in this milestone implies that a real learner reproduced
tutorial step 2.

**Routes** (exact edges and sentences fixed in the IS1 spec):
- *into* the skill, from a row of the `gnd-orm-core` workflow index table
  (p1), the `gnd-export` ILP paragraph, the `gnd-dev-session` grounding
  paragraph, `gnd-solve` Station 6, and the `gnd-model-evolve` induced-provenance
  bullets;
- *out of* the skill, to `gnd-model-evolve` (the handoff), `gnd-orm-core` and
  its provenance, population and record references and the vendored label
  schema (D3), `gnd-export` (derivation and Lean exports are not this skill) and
  `gnd-dev-session` (measure over a synth corpus is not this skill).

`gnd-solve` gets no new station number (D7); the stable station numbers stay
pinned by `test_t25`.
