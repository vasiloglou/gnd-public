The proposed primary optimization is feasible. Current preparation normalizes and measures policy once, but reuse later hashes the whole signature, then measures its policy subtree before and after cloning every miss. Verified metadata for the immutable normalized representation can remove these repeated walks while retaining structural signature equality and live function-code/mutable-leaf checks. Exact builtin dispatch can avoid dataclass reflection without changing handling of trusted GND records. The spec explicitly keeps actual private-clone measurement, which is necessary because reconstruction changes allocation sizes.

The hard correctness boundaries are preserved in the written contract: full payload/exit/branch and ordered calculation parity; fixed 4,878 reporter denominator; fresh current model/options validation; ownership/authority; cancellation and atomic publication; clone detachment; unsupported fresh fallback; original quotas; unknown-hook conservatism. No eligibility expansion or inference of safe per-transaction mutation checking is proposed. The optional correspondence/extension setup work is explicitly conditional and may be deferred if live mutation guards cannot be preserved. That makes the bounded primary implementation achievable without requiring an unproven whole-context purity mechanism.

Implementation hardening and completeness checks, not approval blockers:

1. A precomputed policy summary must preserve enclosing depth/node limits, not only standalone policy validity. Current _measure counts each visited edge before deduplicating storage; size deduplication and occurrence/work accounting are different. A policy individually below MAX_DEPTH/MAX_NODES can cross a limit when embedded in an entry. Add boundary controls with wrappers/residual content and repeated references, and ensure the fast path cannot make an otherwise refused key reusable. The spec already requires unchanged node/depth/cycle refusal and real visit controls; these are concrete cases for that obligation.

2. Cached metadata must describe only the immutable normalized policy, including its wrapper/metadata allocation. A caller-controlled object or forged summary must not bypass bounded normalization. Keep authority on prepared policies, refuse foreign/expired handles, and retain live code plus mutable defaults/configuration checks at every actual lookup. Hash collisions must still compare structural content. The stated metadata design and collision test cover the right requirement; implementation will determine whether it is met.

3. Conservative per-entry charging may overcount shared policy storage, which is permitted, but accounting must still include old committed entries plus proposed new entries on a miss and both bindings on changed options/model content. Current reuse's retained-entry union and transaction's working binding charge are the relevant owners. Preserve the existing private-clone and changed-binding tests and add a large-policy multi-entry/cap control; a cheaper size estimator alone does not establish the retained-state bound.

4. Performance tests should count actual recursive accounting/policy work, not merely calls to a wrapper that hides an unchanged full walk. A metadata-construction walk once per preparation is legitimate and must remain visible in total diagnostic accounting. Snapshot fingerprinting and mutable guards remain real work even if policy walks disappear. The planned pre-fix RED tests plus current integrated observer boundary are suitable instruments.

The IE6 contract correctly makes deterministic bookkeeping reduction and complete parity hard gates while reporting balanced same-host elapsed results without an invented speed factor.
