The main implementability risks have explicit prerequisites:

- **Dependency support exists, without pretending constraint metadata is already complete.** `src/gnd/model/_validation.py:3294` exposes positive, negative and aggregate edges; `src/gnd/model/_validation.py:3585` supplies deterministic SCC-condensed strata. The plan requires missing implicit/roster/reference dependencies to be inventoried, conservatively classified or evaluated fresh (`.gnd-planning/milestones/incremental-evaluation/notes/incremental-evaluation-plan.md:129`, `:192`, `:203`). IE0 and IE1 therefore precede reuse rather than relying on an unsupported completeness claim.
- **Existing refresh machinery is usable but insufficient; the sequence recognizes that distinction.** `src/gnd/extensions.py:1336` already recomputes selected SCCs from empty computed relations, supporting deletion without requiring a new retraction engine. However, `src/gnd/extensions.py:2024` rebuilds supplied prior relations with empty lineage. The plan expressly identifies that limitation (`incremental-evaluation-plan.md:138`) and makes a complete envelope an IE2 deliverable and an IE3 prerequisite (`:162`, `:219`). This is substantive implementation work, but not a circular prerequisite or impossible contract.
- **The proposed layering can be implemented within the existing map.** The layer map places model/dependency queries in `model`, extensions/checker/correspondence in `checking`, `checking_service` and transitions in `semantics`, and API entry points in `entry`. The proposed homes and prohibition on lower-layer imports of API or persistent experiment sessions (`incremental-evaluation-plan.md:165`, `:177`) permit a session facade in the semantics layer with lower-layer reusable state. No additional layer allowance is inherently required.
- **Transition integration has observable obligations that the plan retains.** Current transition execution checks the root at `src/gnd/transition.py:1927`, every loadable intermediate at `:2024`, and the declared post after frame grading at `:2052`. IE-R3 and IE3-C1 explicitly preserve these checks and their ordering (`incremental-evaluation-plan.md:58`, `:229`), while allowing selective internal work. Existing same-call `CalculationScope` remains ephemeral (`src/gnd/extension_preparation.py:153`); the plan does not propose silently turning it into cross-call ownership (`incremental-evaluation-plan.md:177`).
- **Reporter savings are an unresolved experiment, not an unsupported implementation guarantee.** The strict counted target includes an explicit feasibility return gate before optimization (`incremental-evaluation-plan.md:33`). IE0 must freeze measured denominators and achievable targets (`:196`), while its spec forbids inferring body execution from selected heads and requires counter liveness (`.gnd-planning/milestones/incremental-evaluation/notes/phase-IE0-spec.md:124`). The existing public workload and driver support that investigation; static inspection cannot establish the eventual savings.
