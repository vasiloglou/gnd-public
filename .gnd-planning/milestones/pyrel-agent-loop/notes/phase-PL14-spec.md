## 4. Standing rules, bound

1. **Totality.** Every new term shape is validated. DateTime, nested date
   terms, opaque cells and the float tier are refused by name.
2. **Bounds.**
   - GND's 10,000 date-function applications per rule are mirrored: past
     them, the rule is unchecked with `term:temporal-work-limit`.
   - Reference size limits are GND's own, because binding goes through
     `gnd.references.bind_references`.
3. **Validation order.** `load_model_bytes`, then reference binding, then
   lowering.
4. **One walk.** Typed literals are resolved once, at lowering.
5. **One home.** One function renders a typed term (§6.2), for guarded
   comparisons and for derivation `where` alike.
6. **Measurement.** A corpus generated by `gnd.api.check` (§8, row 1).

## 5. GND's semantics this phase reproduces (measured)

- **Date values.** Population cells are `YYYY-MM-DD` and must be real Gregorian
  days. A Date's identity token is its string, so witnesses print dates as ISO
  strings. Dates compare as dates.
- **Duration values.** An Integer number of days, from 0 to 1,000,000.
- **Where temporal terms may appear.** Tagged literals (`{date: ...}`,
  `{duration_days: n}`) and `date_add`/`date_sub` are allowed only in guarded
  comparison operands of a version 3 or 4 model.
- **Untagged literals.** An ISO string compared with a Date variable in a guarded
  rule is a date. GND's validator refuses one in a derivation `where`
  (amendment A5).
- **Date arithmetic.** `date_add`/`date_sub` move by whole proleptic Gregorian
  days.
- **Out of range.** If any binding's result leaves 0001-01-01..9999-12-31, the
  whole rule is unchecked (`term:date-out-of-range`), with no witness, even
  when other bindings fail (measured, `mix-fail-oor`).
- **Work limit.** Past 10,000 date-function applications in one rule, the rule
  is unchecked (`term:temporal-work-limit`).
- **References.**
  - The model declares `reference_populations` (`id`, `path`, `sha256`,
    `fact_types`).
  - GND binds them before checking. A tampered or missing file, or a wrong
    identity, gives exit 3.
  - A candidate that mentions an owned fact type gives exit 3.
  - Constraints and derivations read the candidate plus the reference facts,
    and reference covers are merged.

## 6. Design

### 6.1 Dates in the programs

- Date roles become PyRel `Date` fields. Duration roles become `Integer` days.
- The program checks each cell (strict ISO date; Duration an integer from 0 to
  1,000,000) and converts dates to `datetime.date` before loading. Loading ISO
  strings into a PyRel Date field breaks every later query (measured).
- Rows are printed with dates as ISO strings, so witnesses and their order
  match GND's string identity.
- Date literals render as `datetime.date(Y, M, D)`. That applies to tagged
  literals, untagged ISO strings typed by the Date variable they meet, and Date
  value ranges and allowed lists.
- DateTime is refused by name: it brings offsets and naive/aware cases, and no
  example needs it.

### 6.2 Terms in guarded comparisons

A guarded comparison operand may now be:
- a variable;
- a literal;
- a tagged date or duration;
- `date_add(x, d)` or `date_sub(x, d)`, where `x` is a Date variable or literal
  and `d` is a Duration variable or literal (not nested);
- Integer `add`, `sub`, `mul`, `neg` and `abs`.

`date_add(x, d)` renders as `std_date.add(x, days(d))`, and `date_sub` as
`std_date.subtract(...)`. For a rule that uses date functions, the program also
lists the antecedent's bindings. From them the report decides:
- the work limit, as bindings times the number of date functions, against
  10,000;
- the range, as each binding's results, with exact ordinals computed in Python.

If either fails, the rule is printed as not checked, and an alethic one raises
exit 4. Otherwise the requirement's denial rows decide the verdict.

### 6.3 Reference populations

- **At export.** The generator calls `bind_references(model, root=<model's
  folder>)`. Its refusals (hash mismatch, missing file, identity, limits) stop
  the export by name, with exit 3.
- **Embedded snapshot.** The bound reference facts, instances and covers are
  written into the program as a snapshot, with the id and SHA-256 of each file
  in a header comment.
- **At run time.** The program refuses a candidate that mentions an owned fact
  type (exit 3, GND's message). It then merges the reference facts, instances
  and covers before loading.
- **Consequence.** The program is self-contained. A change to a reference file
  after export needs a new export, and the header says so.

## 7. Decisions

| # | Question | Ruling |
|---|---|---|
| D1 | Date encoding | native PyRel `Date`. Requirements read as dates (`std_date.add(start, days(30))`), and range checks happen in the report, so PyRel never has to compute an out-of-range date for a verdict |
| D2 | Float tier, `avg`, exact Float arithmetic (PL13b-Q3) | stay refused by name. Measured differences: PyRel rounds half away from zero where GND rounds half to even, divides by zero to ±inf, crashes on `sqrt` of a negative, and `avg` is a 6-digit decimal. PyRel's `haversine` returns 2r for every input. No example needs them |
| D3 | References bound at run time or at export | at export, with GND's own binding. The program states the hashes it was built from |
| D4 | DateTime | refused by name |
| D5 | Opaque cells | stay refused by name (PL13b) |
