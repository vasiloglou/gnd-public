## Proposed interfaces and behavior

Keep existing developer-owned extension.py/reporting.py/currency_reporting.py
and default GND backend behavior. Add --backend pyrel and required explicit
--pyrel-python to report/approve subcommands. A separately packaged native_query.py
has no GND import, loads the exported runtime, admits the declared profile, and
uses native relationships and aggregates. The parent owns bounded processes,
source capture, independent --accept verification and atomic publication.
The CLI locates its owned native query beside its copied extension; tutorial
setup must copy that file too. Interpreter and business options are public flags;
arbitrary query selection and fault injection are not CLI options.

Native report computes distinct submitted expense count, approved expense count,
and totals over submitted expense/amount joins. Include expense identity in sum
projection, so repeated amounts across different expenses remain separate.
Baseline units are explicitly implicit EUR; evolved units are explicit EUR and
output is totals_by_currency with EUR key. No exchange rates or conversion.
Native non-EUR presence refuses before reporting any successful total; framework
supported_currency/mandatory constraints remain the separate acceptance gate.
Queries do not silently fill missing asserted coverage or currency facts.

Approve checks submitted/already-approved membership using native queries;
unknown expense and duplicate approval refuse1. It appends an approval and chain
claim as application orchestration, then checks the complete candidate under the
selected model. Chain/category/amount/submitter validity resides in model policy,
not duplicated Python predicates. This creates an accepted static snapshot;
it does not authorize the current actor, transfer money or prove a transition.

Application guard refusals need an explicit source-bound artifact, because a
query process crash1 must remain operational70 (PA3 F3). Extend proposal schema1
with a mutually exclusive refusal envelope: schema_version/binding plus
guard_refusal containing exit_code1, a bounded nonempty kind and reason; no
candidate/calculation may accompany it. The query writes this artifact and exits0
after its native membership/currency query finds the declared guard condition.
The parent verifies exact model/input binding and strict refusal shape, returns
accepted=false/published=false/application_refusal evidence and never invokes
publication. This is an application guard, not a framework policy verdict.
Nonzero process1 is still70. Add red controls for malformed/misbound/mixed/unknown
guard envelopes before implementation. No BookRec or expense predicate moves
into the shared parent; its new logic validates only the versioned envelope.

Reports reuse execute_application with a private output in a temporary directory:
the unchanged source population becomes the checked candidate. Only accepted
reports print business arithmetic with exit0. On refusal the CLI prints policy
or bounded diagnostic evidence, withholds successful report arithmetic, and
preserves the input. Approval publishes to a fresh explicitly named output only.
