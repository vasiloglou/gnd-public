# GND development agreements

Use [process-phase](.codex/skills/process-phase/SKILL.md) for numbered milestone work.
The complete normative references are shipped in both real discovery roots;
keep twins byte-for-byte and executable-mode identical. The owned compatibility
[plan-review-panel](.codex/skills/plan-review-panel/SKILL.md) requires an explicit
handoff to the maintained advisory panel. No automatic sibling execution.

Default `auto=false`; owner approval precedes implementation. User authorization
persists for its named scope; never invent approval. Read the whole effective
plan and applicable carryovers when harvesting a phase. Plan authorship is not
publication authority. Certification/recertification needs an explicit current
owner request for a named subject and scope; old certificates describe old bytes.

Credential-free development follows CONTRIBUTING. Optional live review uses the
explicitly selected terminal-agent tools and credentials; never execute or source a repository `.env`.
Import only required names from a documented trusted environment, never print
values. The maintained panel requires parent credentials; its explicit launcher
may parse the owner's trusted Codex file as data before invocation.

GND-managed discovery links are generated by the own installer. On a fresh clone,
adopt tracked links once with uv run gnd install --symlink --project --force,
then uv run gnd doctor --project. Receipts are machine-local and gitignored.
Never maintain links by hand. Source-owned units remain source-owned
until an explicit accepted handoff. Release preparation does not enable a production publisher.

## Pull requests are required

All contributors, including coding agents and administrators, work in a fork or
topic branch and submit a pull request. Never push directly to main, force-push
main, or delete it. GitHub protection requires a PR and successful required CI;
resolve review conversations before merging. Web edits also use a branch and PR.
No standing contributor bypass is allowed. Approval to perform phase work does
not waive this rule. Repository owners can change settings, so configuration
must be checked before claiming enforcement.

## Refactoring dependency homes

Use tools/gnd_layers.json for module assignments and runtime import checks,
including lazy and literal dynamic imports. Keep new homes in the map and keep
the allowance count at zero. Shared data/lookup live in documents, values and
universe; extension calculation lives below checker; applicability consumes its
public effective_view. Descriptor registration lives in branches. Retain moved
names as explicit identity aliases in the milestone shim inventory; patch the
defining home or actual public lookup, and preserve source-scan visitation.
Shim retirement follows RF-D5 in the approved refactoring plan.

RF4 peripheral homes: safefs provides public filesystem seams without merging
variants; process owns bounded execution, agents owns trusted adapter selection.
The synthesis oracle and ordered assurance package retain historical imports.
Update actual patch lookup owners and include new homes in source-scan coverage.
